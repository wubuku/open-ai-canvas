# 影策技能广场与 Skill 运行机制调研

> **目的**：帮助创作者判断 `/skills` 中的技能适不适合当前任务、怎样让创作入口实际使用它，并帮助开发者区分技能说明、上下文加载和真实工具执行。
> **状态**：研究草稿；技能广场目录随服务端发布内容变化。
> **证据范围**：当前仓库前后端源码、内置技能包、相关测试，以及 `http://localhost:28300/skills` 的只读浏览器检查。未执行真实 Agent 创作或付费媒体生成。

## 结论

影策的产品 Skill 是一组可以复用的创作流程说明和参考资料。它通常以 `SKILL.md` 为入口，可带有方法卡等文件。选择技能后，系统把其文本内容按路径加载到模型上下文，让模型在本轮任务中参考这些方法。**技能不是可执行插件，也不会自行增加模型、按钮、工具、权限或生成能力。**

对 `/skills` 用户来说，实际过程是：

```text
技能广场查看简介和文件
  -> 加入“我的技能”
  -> 在具体创作任务中选中或提及技能
  -> 当前入口加载技能文本
  -> 模型按现有工具合同组织回答或操作
  -> 真正的画布写入、收费生成和资源回写仍走影策原有服务端链路
```

因此，“广场里能看到”不等于“本轮已使用”，“加入技能库”也不等于“所有任务自动使用”。技能正文里写了某个工具名称，也不会让该工具自动出现。它能否完成其描述的全流程，取决于技能文本是否与当前创作入口及当前服务端真实工具相匹配。

## 1. 先区分三种 Skill

| 名称 | 面向谁 | 当前作用 |
| --- | --- | --- |
| 产品技能广场里的 Skill | 影策创作者 | 用户加入并在具体任务中选择；内容作为工作流指引或参考资料进入生成上下文。 |
| `web/src/services/skill-runtime.ts` | Web 创作入口 | 负责解析当前用户可用的技能、读取文件、把技能文本链接到普通生成提示词，并返回版本和文件来源元数据。调用方是否把这些元数据持久化，取决于具体入口。它是运行适配器，不是技能目录。 |
| 仓库 `.agents/skills/` 中的 Agent Skill | Codex 等仓库协作者 | 指导代码研究、文档编写等开发工作。它不属于产品用户技能。当前 Pi runtime 明确关闭默认 filesystem skills，不会因为仓库里存在 `.agents/skills/` 就把它加载进云端 Agent。 |

本文的主要对象是第一种。云端 Agent 与普通创作入口都能消费产品 Skill，但采用不同加载方式。

## 2. `/skills` 页面上有什么

当前本机开发站点的技能广场接口在 2026-10-11 返回了 **71 个公开技能**。这只是本机服务端当前发布目录的快照，不保证其他环境或后续版本也是 71 个。当前返回的分类数量如下：

| 分类 | 数量 | 常见目标 |
| --- | ---: | --- |
| 短剧影视 | 25 | 故事开发、剧本、分镜、表演、剪辑和短剧生产。 |
| 电商营销 | 12 | 商品图文、带货短视频、品牌定位、广告脚本和转化。 |
| 创意设计 | 23 | 视觉风格、提示词、系列图、特效、珠宝设计和图片编辑。 |
| 社媒内容 | 8 | UGC 穿搭、社媒短片、原创 IP、人物形象和开箱内容。 |
| 其他 | 3 | 动画线稿上色、原创角色诊断、技能选择建议。 |

页面支持搜索、分类和“最多加入 / 最新发布 / 最近更新”排序；详情面板显示技能简介、来源、版本、文件树、文件预览/源码、加入人数和收藏状态。技能说明以 `SKILL.md` 为入口；不能只看名称，应先读简介，再按需要打开具体文件。

页面的几个操作代表不同状态：

- **加入技能库**：为当前用户建立可在创作入口使用的加入关系。后端以 `UserSkillState.Added` 保存；不是立刻执行技能。
- **收藏**：单独记录喜欢状态，不等于加入，也不会使技能成为本轮上下文。
- **技能文件**：技能的说明和参考资料。上传的代码或二进制文件不会因此成为产品插件。
- **我的技能 / 我创建的 / 我的收藏**：`我的技能`包含已加入的他人技能，也包含本人创建且始终保留在库中的技能；`我创建的`是按创建者筛出的子集；收藏关系可与前两者重叠。它们不是三个不同的运行时。

## 3. 实际使用方法

### 3.1 从技能广场加入

1. 打开 `/skills`，按类别、名称或描述搜索候选技能。
2. 点开技能卡，检查简介、适用范围和 `SKILL.md`。若包里有方法卡或参考文件，按本次任务查看相关文件。
3. 对他人发布的技能点击“加入技能库”；本人创建的技能已默认保留在“我的技能”中，不需要再加入。
4. 到实际创作入口中选中/提及技能。只加入而不选，不会把技能正文自动附到每条任务。

### 3.2 在画布云端 Agent 使用

打开画布 Agent 的技能库，可浏览市场、已加入技能和本轮已选技能。选择要用于本轮对话的技能后再发送任务；输入框也支持 `/关键词` 搜索技能并插入，或用 `@` 引用技能。预设场景胶囊会按预设装入所需技能；缺少的技能会先加入当前用户技能库，再选入会话。

提交时前端把技能 ID 放入 Agent run 请求。后端检查技能是否已加入且仍处于发布状态，然后冻结本轮技能的版本 ID、内容 hash 和允许读取的文本路径。模型先看到技能名称、描述和路径；需要具体方法时才调用 `skill_search`、`skill_read_file`。这条路径适合多步创作、画布读写和需要服务端 Agent 工具的工作。

### 3.3 在普通创作和生成入口使用

画布普通生成可以从 `@` 技能引用解析本轮技能；项目分镜与制作工作台提供“本次生成使用的技能”选择器；首页创作 Agent 也会把选中的技能加入本次规划上下文。调用统一 `skillRuntime` 的入口只处理 `isAdded` 的技能；当前服务端会把本人创建的技能也标记为可用，因此它们无需另行加入。

普通入口会把 `SKILL.md` 和少量相关文本文件放进生成提示词，随后仍通过该入口原有的模型/生成服务提交。因此它适合给提示词和文本流程添加方法约束；不能把它当成云端 Agent 工具调用能力的替代品。当前统一运行适配器最多选 4 个技能，所选文件正文的总预算为 32,000 字符，每个技能最多再链接 3 个相关文件（外围标签和固定说明不计入正文预算）。适配器会返回技能 ID、版本和已加载文件路径/SHA-256；画布、首页生成等部分调用方会把它们传入任务或节点元数据，首页创作 Agent 的规划路径则只使用准备后的提示词。不能据此假定所有入口都保存了完整 provenance。

### 3.4 选择示例

| 目标 | 可先试的技能 | 怎么给任务 |
| --- | --- | --- |
| 从一句话推进到短剧方案 | 影策短剧制作工作流 | 给出题材、目标时长、已有文本/小说章节和希望先确认的环节；优先通过画布云端 Agent 使用，因为任务可能需要画布、分镜和生成工具。 |
| 修改画布中的一张图片 | 图片编辑工作流 | 先在画布选中/引用图片节点，再说明要改变什么、哪些主体/文字/构图必须保留；用云端 Agent 时，真实生成仍须通过生成审批。 |
| 为服装规划试穿短片 | 穿搭上身试穿视频生成 | 提供服装图、模特参考图、目标平台和想保留的服装细节；先检查技能包提到的工具是否与当前入口相符，再决定用 Agent 生成或只用普通创作入口起草提示词。 |
| 只改善故事结构，不生成媒体 | 故事开发 或 故事结构引擎 | 提供现有梗概、人物和希望解决的问题，明确需要诊断还是从零开发。 |

初次使用时建议选一个主技能，确认输出符合预期后再叠加第二个。多个技能的要求会共同进入模型上下文；风格、格式或阶段要求冲突时，模型可能折中或遗漏。

## 4. 两条运行路径如何工作

### 4.1 云端 Agent：服务端冻结，模型按需读取

1. 浏览器在本轮请求中传 `skillIds`；选中和提及的技能会合并去重。
2. Go 服务端校验技能属于当前用户可见范围、已加入且处于有效发布状态。
3. 服务端读取版本和文件清单，形成带版本 ID、内容 hash 的本轮快照；读取期间若版本变化则拒绝创建混合版本的快照。
4. 初始上下文只包含技能名称、描述、版本、hash 和可读路径，不一次性塞入所有正文。
5. `skill_search` 在本轮已选技能的名称、描述和文件名中做轻量检索，返回候选路径/索引；它不调用外部搜索模型。
6. `skill_read_file` 只读取本轮快照允许的文件路径，按页返回文本；服务端再次核对用户加入状态、版本和 hash。
7. 工具回执记录技能 ID 和路径，不把完整正文复制进 SSE 事件。

Pi runtime 通过 Go bridge 使用服务端给出的工具合同。当前 runtime 明确关闭默认 filesystem skills 和上下文文件发现；仓库中的 `.agents/skills` 不会自动变成产品技能。

### 4.2 普通创作入口：前端加载并链接到 prompt

`skillRuntime.prepare` 根据入口 profile 找出本轮明确选择的技能（或画布 prompt 中的技能引用），先读取 `SKILL.md`，再根据入口引用的文件路径、任务关键词和“必须先阅读”提示挑选少量文本文件。文件包在 `<skill-context>` / `<skill-file>` 标签中，作为用户任务前的上下文交给模型。适配器同时返回版本与文件 provenance；各调用方是否将其写入任务或画布元数据并不一致。

这条路径不执行技能包里的代码，也不开放 Agent 工具循环。引用的图片/二进制文件、`scripts/` 和 `assets/` 路径不会因此变成模型可调用的运行资源；未被入口筛选出的参考文件也不会自动进入 prompt。超出预算的文件会被截断。

## 5. 能力边界与使用风险

### 技能文本不会扩展工具权限

技能包的 `SKILL.md` 是模型上下文数据，不是服务端授权配置。云端 Agent 的工具表由 Go 端按权限模式、上下文、能力和预算创建；画布写入、媒体生成、审批、价格、额度和资源归属由服务端再次校验。技能文本不能授权删除节点、越过媒体审批或使用未公开工具。

### 技能中写的工具名称需要核对

本轮实读的内置技能 `叙事短片导演分镜` 列出了 `request_user_input`、`cloud_research`、`load_skill`、`canvas_write`、`cloud_generation`、`resource_status`、`canvas_present`、`video_editor` 等工具名。当前云端 Agent 工具表里对应能力使用的是 `ask_user`、`generate_media`、`task_get` 和受限的 `canvas_*` 工具；没有与上述旧名称一一对应的通用工具。技能包写这些名称不会让它们可调用。

相对地，`图片编辑工作流` 和 `影策短剧制作工作流` 的部分步骤使用了当前 Agent 的 `canvas_get_state`、`ask_user`、`canvas_apply_ops`、`canvas_create_storyboard`、`generate_media` 等合同。但这仍只能证明文本与当前工具名较匹配，不构成完整真实生成验收。

### 简介中的承诺不等于产品已经具备该能力

广场简介和 `SKILL.md` 可能描述表单、批量生成、视频剪辑、自动工具装载或产物回写。应确认：

- 当前入口是否有这项交互或工具；
- 工具是否在当前运行实际注册并可调用；
- 输入资源和模型是否满足其前置条件；
- 媒体审批、计费和结果回写是否遵守现有链路；
- 本轮选中的模型是否支持所需图片/视频/音频能力。

云端 Agent 的媒体生成要通过已有 `generate_media`、模型准入和独立审批；普通创作入口则按自身既有任务提交流程工作。选择技能不会自动提交生成，也不意味着生成免费或一定成功。
